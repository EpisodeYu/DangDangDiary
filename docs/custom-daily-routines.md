# 自定义日常事项（2026-10）

本文取代 Step 5 中“日常固定三类”的约定。预置项为“洗澡”“剪指甲”，不可重命名或删除，仍可设置周期、提醒和记录。

## 使用规则

- 每只宠物最多 10 个未删除的自定义事项。已有档案的“梳毛”迁移为自定义项，占一个名额，保留全部历史、周期和提醒开关；新档案不创建“梳毛”。
- 点击日常列表下方“新增日常事项”，只输入名称即可保存。初始周期未设置、提醒关闭。
- 名称去除首尾空白并规范化，限 1–20 个可见字符，同一宠物的有效事项不允许重名（包括预置项）。
- 自定义项可重命名、删除。删除前确认；删除后关闭提醒、释放名额，保留历史和原周期。再次创建同名事项使用新的标识，历史不混合。
- 主人和编辑成员可管理、设周期和记录；查看成员仅可查看。后端对每个写入口校验权限。
- 已删除事项不可新增记录；已有记录仍可查看、调整日期或删除。
- 周期范围 1–365 天，留空表示未设置。提醒沿用原健康提醒规则；无周期或无记录时不安排通知。
- 语音识别候选来自各宠物当前有效事项；不自动创建事项。确认时再次校验事项和权限，识别后删除的事项不能写入。

## 数据与接口

`routine_items` 保存宠物范围内的稳定 `routine_type`、名称、周期、提醒和软删除时间。新标识为 `custom_<uuid>`，旧“梳毛”保留 `grooming` 标识。历史 `routines.routine_type` 从 PostgreSQL 枚举转为字符串。

接口均位于现有 `/api/v1` 前缀下：

| 请求 | 行为 |
| --- | --- |
| `GET /pets/{id}/routine-status` | `items` 包含两个预置项和当前有效自定义项及状态 |
| `POST /pets/{id}/routine-items` | `{ "name": "刷牙" }`，返回完整定义 |
| `PUT /pets/{id}/routine-items/{routine_type}` | 更新名称、`cycle_days` 或 `reminder_enabled` |
| `DELETE /pets/{id}/routine-items/{routine_type}` | 软删除并停止提醒，返回 204 |
| `PUT /pets/{id}/routine-cycle` | `items` 数组批量保存周期与提醒，整批成功或回滚 |
| 现有日常记录接口 | `routine_type` 接受有效事项标识；响应增加 `routine_name`、`routine_deleted` |

上限和重名检查在宠物行锁下执行，跨连接并发不能突破限制。状态使用一次分组聚合查询获取所有事项最近记录。

导出 JSON 的 `records.routine_items` 包含预置、自定义及已删除定义；`records.routines` 包含完整历史和名称、删除标记。字段为增量扩展，保留 `schema_version: 1` 和原字段。

## 部署

1. 备份数据库，暂停旧后端写入。
2. 在后端环境运行 `alembic upgrade head`，迁移至 `c9d0e1f2a3b4`，启动匹配的新后端。
3. 再安装新版 App。旧后端不支持新增接口；旧 App 无法完整理解自定义事项，前后端应配套更新。

迁移保留旧枚举及宠物的梳毛字段。若已有新增、重命名或删除的自定义数据，降级迁移会拒绝执行，避免丢失数据；需要回退时使用部署前备份。

## 验证

- 后端 API 测试覆盖上限、重复名、跨宠物隔离、权限、周期、软删除、历史导出和语音确认。
- 可选真实 PostgreSQL 测试：在本机独立测试库设置 `CUSTOM_ROUTINE_TEST_DATABASE_URL=postgresql+asyncpg://<用户>:<密码>@127.0.0.1:<端口>/<测试库>` 后运行 `pytest tests/integration/test_custom_routine_postgres.py -q`。仅接受本机地址，每个测试使用独立临时 schema。
- Flutter 测试覆盖管理交互、周期留空、记录、语音确认、只读权限、10 个长名称及大字体、提醒取消、ZIP JSON。
- Android 集成测试使用合成档案及内存服务，覆盖新增→周期→记录→改名→删除→查看保留历史；通过 `test_driver/custom_routines_driver.dart` 保存截图。后端持久化由 API 与真实数据库测试覆盖。
- 云端语音服务使用 mock 测试候选传递及确认流程，不调用真实付费服务。
